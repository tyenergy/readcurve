# ReadCurve 作为"论文复现"工具的使用说明（面向 Agent / Skill）

本文档描述如何在自动化流程（例如 Claude Code 的论文复现 skill）里调用 ReadCurve，
从论文图表中提取曲线数据。全部功能都有命令行入口，不需要打开图形界面。

## 1. 环境

```bash
pip install -r requirements.txt      # numpy, Pillow, rapidocr_onnxruntime(可选但推荐)
```

依赖都是纯 pip 包，无需系统级安装。首次 OCR 约需 1 秒初始化。

## 2. 推荐流程

```
看图(Agent 自己看) → 必要时裁出单个子图 → 一键识别 → 看核对图与日志 → 补刻度/修正 → 读取 CSV
```

### 第 1 步：多子图先拆分

ReadCurve 一次只处理**一个坐标系**。论文里常见的 (a)(b)(c)(d) 多子图，用 `--panels` 自动拆分：

```bash
python auto_detect.py fig.png --panels -o out.csv --preview check.png     # 每个面板输出 out_a.csv / check_a.png …
python auto_detect.py fig.png --panel b -o out.csv --preview check.png    # 只处理面板 b
```

程序找出所有"左下角相接的一横一竖长线"作为坐标系，按先上后下、先左后右编号 a, b, c…，
照片/插图的边缘和图例框会被过滤。不加参数时若检测到多个面板，日志会提示并列出各面板位置。
面板漏检（例如坐标轴是浅灰色）时退回手动裁剪：

```bash
python auto_detect.py fig.png --crop x0,y0,x1,y1 -o out.csv --preview check.png
```

`--crop` 用像素坐标（也可用 0~1 的比例），裁剪框要**包含刻度数字**但**不要包含面板的外框线**。
拆分或裁剪后，该面板的所有像素坐标（日志、`--cal`）都以裁剪后的图为准。

### 第 2 步：一键识别

```bash
python auto_detect.py fig.png -o out.csv --preview check.png
```

程序会打印日志，关键几行：

```
绘图区: x 103~648, y 24~461，X 轴行 463，Y 轴列 101     ← 找到的坐标轴
X 轴刻度线 9 个: 103, 171, ...                            ← 检测到的刻度线像素位置
X 轴：线性，用 18/18 个刻度 [5.2, 5.3, ..., 6]             ← OCR 标定成功
Y 轴：线性，用 13/13 个刻度 [-30, -25, ..., 0]
检测到插图/照片等实心区域，占绘图区 19%，已排除            ← 图中照片/模型图已自动排除
识别到 2 条曲线：曲线1(3, 2, 3) 527点、曲线2(255, 1, 1) 541点
已导出: out.csv
```

**一定要看 `check.png`**：曲线用洋红色描出、标定线用橙色、刻度线用蓝色、排除区绿色。
Agent 应把核对图与原图比对：曲线是否被完整描出、有没有串到别的线/图例上、标定线是否落在正确刻度。

### 第 3 步：标定失败时，补刻度值

OCR 读不出刻度的典型情况：刻度数字很小、数字之间太密（连成一串）、对数轴用上标（10³）、数字被裁掉。
日志会告诉你原因并列出可用的锚点，三种补救方式按优先级：

1. **给刻度值，让程序对应刻度线**（最省事）：
   ```bash
   # 全部刻度值（个数需与"检测到的刻度线"或"轴旁文本"个数一致），或只给首尾两个
   python auto_detect.py fig.png --xticks=0,10,20,30,40 --yticks=0.001,0.01,0.1,1,10 --logy -o out.csv --preview check.png
   ```
   负数开头的值用 `--xticks=-100,100` 的等号写法，否则会被当成选项。
   日志会说明匹配了哪些锚点（"首尾两个刻度值对应最外侧的刻度线（287 px 与 105 px，共 5 个锚点，请核对）"），
   **锚点个数与图上刻度个数不符时不要采信**，改用方式 2。

2. **直接给像素位置**：日志里的"X 轴旁文本(像素x@文本)"列出了 OCR 看到的每个文本及其像素位置，
   例如 `474@'10', 534@'10', ... 710@'10'` 是对数轴丢了上标的五个标签，Agent 自己读图确定它们是
   10¹ … 10⁻³ 后：
   ```bash
   python auto_detect.py fig.png --cal "x:59=-100,240=100;logy:474=10,710=0.001" -o out.csv
   ```
   `x:`/`y:` 线性，`logx:`/`logy:` 对数；每轴两对 `像素=数值`，取相距最远的两个刻度最准。

3. **重新裁剪**让刻度数字完整进入画面（例如对数轴的 "10" 和上标都要包含）再回到第 2 步。

### 第 4 步：曲线不对时

| 现象 | 处理 |
|---|---|
| 少了一条曲线 | 黑/灰色曲线贴着坐标轴或文字时可能漏掉；在 GUI 里点一下那条线，或 `--tol` 调大 |
| 曲线很密/很粗被当成实心区域排除（日志提示） | 加 `--no-exclude` |
| 两条同色曲线交叉后串线 | 程序按颜色+走向区分，仍串线时裁小区域分段提取，或用 GUI 手动取点 |
| 多出假曲线（图例线、网格） | 假曲线通常点数少、跨度短；按 CSV 列名删掉即可 |
| 曲线在插图处断开 | 正常：插图区域被排除，穿过部分按间断处理，两侧自动接上 |

### 第 5 步：读取结果

默认 `--mode separate`：每条曲线两列 `曲线N_x, 曲线N_y`，行数不等时补空。
需要对比多条曲线时用 `--mode common --n 200`：统一插值到同一组 x（200 点）。
`.csv` 逗号分隔，`.txt`/`.dat` 制表符分隔。未标定时导出的是**像素坐标**，日志会有"警告"。

**曲线命名**：程序会 OCR 图例文字，并检查文字左侧的线条/标记样本是哪条曲线的颜色，
匹配上的曲线直接用图例文字命名（日志：`曲线2 → 'measurement'（图例，185 像素匹配）`），
CSV 列名随之变为 `measurement_x, measurement_y`。没匹配上的仍叫"曲线N"，这时 Agent 需要
对照日志里的颜色 (RGB) 和图例自行映射。OCR 偶有误读（如 "0-PLA" 读成 "O-PLA"），以图例原文为准。

**质量指标**：每条曲线日志里带 `[覆盖99% 密度1.00 断口0]`，`summary.json` 里是 `coverage / density / gaps`：
- 覆盖 = 曲线跨度 / 绘图区宽度。实际曲线本身不贯穿全图时偏低是正常的；
- 密度 = 点数 / 跨度。实线接近 1，虚线 0.5 左右，点线 0.2~0.4；明显低于预期说明追踪断断续续；
- 断口 = 连续缺失 ≥5 列的次数。虚线/点线天然有断口；实线出现断口多半是被插图或文字遮挡。
密度 < 0.3 且断口很多的实线、或覆盖率远低于图上所见的曲线，应人工核对核对图。

## 2b. 表格图片 → CSV

论文里以图片形式出现的表格用 `table_ocr.py`：

```bash
python table_ocr.py table.png -o table.csv --parsed table_num.csv --preview check.png [--crop x0,y0,x1,y1]
```

- `table.csv`：原文单元格。`--parsed`：数值解析版，每个单元格占两列（值, 误差），
  能解析 `120 ± 5`、`3.2×10^-3`、`4.9e-3`、`85.3%`（→0.853）、`1,234`、负号/Unicode 减号；解析不了的保留原文、误差列留空。
- 分行：按文字块纵向位置聚类，三线表的横线作为额外分隔；有完整网格线（≥3 横 ≥2 竖）时直接按线带分行，
  单元格内换行的文字会拼回一格（数字续行不加空格）。
- 分列：统计每个横坐标被多少行文字覆盖，很少被覆盖的竖向空带是列间隙，所以跨列的合并表头不会把两列粘住；有竖线时按竖线分列。
- 日志给出 `N 行 × M 列` 和跨列文字块数；核对图里行带交替绿/蓝、列线橙色、文字框洋红。
  Agent 应核对：行列数是否与图一致、表头是否被拆散、数字是否被截断。
- 局限：合并单元格只会落在起始列；无线表格中单元格内换行会被拆成两行；小字号或非常规字体下 OCR
  可能混淆 1/l、0/O、GHz/ZH5 之类，关键数值请对照原图；旋转的表格需先转正。

测试记录：两张合成表（三线表含 ±/×10^n/科学计数法/负数；中文网格表）与三张 arXiv 论文表格图片
（无线条的超参数表、带网格线且单元格换行的结果表、带标题行的分类指标表）行列结构全部正确，
数值单元格全部解析正确；合成中文表里两个小字号英文单位被误读（GHz→ZH5）。

## 3. 批处理

```bash
python batch_digitize.py figs_dir/ another.png -o out_dir/ [--crop ...] [--no-ocr]
```

每张图输出 `<name>_data.csv` 与 `<name>_check.png`，并生成 `out_dir/summary.json`
（绘图区、是否标定、曲线列表、日志），适合 Agent 程序化读取后决定哪些图需要人工补刻度。

## 4. 精度与适用范围

- 采样方式是逐像素列取线条中心，精度约 1 像素（标定误差通常 < 0.5 像素）。
  600 像素宽的图、x 跨度 10 → 分辨率约 0.02。曲线很陡处误差会大一些。
- 支持：实线/虚线/点线、带数据标记（空心/实心方块圆点）、线性/对数轴、图例在图内、照片/模型插图、
  JPEG 压缩图、网页截图风格的灰色网格。
- 不支持/需人工：多子图整体处理（先裁）、歪斜扫描图（先旋转）、同一颜色的多条曲线交叉、
  双 Y 轴（分两次标定）、极坐标/三维图、柱状图（不是曲线）。
- 黑色曲线可以自动提取，但若与黑色图例框、文字贴得很近，交界处个别点可能偏移。

## 5. 在 Python 里调用

```python
import numpy as np
from PIL import Image
from auto_detect import auto_digitize, save_preview
from curve_core import AxisCalibration, export_csv

rgb = np.asarray(Image.open("fig.png").convert("RGB"))
res = auto_digitize(rgb)                       # 或 auto_digitize(rgb, xticks=[0, 40], yticks=[0, 1])
print("\n".join(res.log))
if res.calibration is not None:
    for c in res.curves:
        x, y = c.data(res.calibration)         # numpy 数组
    export_csv("out.csv", res.curves, res.calibration)
save_preview(rgb, res, "check.png")
```

`auto_digitize` 参数：`use_ocr, tol, max_jump, max_gap, max_run, exclude_dense, calibration, xticks, yticks, log_x, log_y`。
返回 `AutoResult(frame, calibration, curves, labels, log, exclude)`。

## 6. 真实论文图测试记录（2026-10）

图片来自开放获取论文（PMC 收录的 MDPI / Scientific Reports 图、arXiv HTML 版论文图）和一张用户提供的论文截图。

| 图 | 来源 / 风格 | 一键自动结果 | 需要的人工动作 |
|---|---|---|---|
| S11 曲线 + 实物照片插图 | 论文截图，黑线空心方块 + 红线实心方块，图例在图内 | 标定 18/18 + 13/13 刻度；2 条曲线完整，照片自动排除 | 无 |
| 训练/验证准确率 | arXiv，matplotlib 默认风格，带圆点/叉号标记 | 标定全部刻度；2 条曲线完整 | 无 |
| 训练/验证损失 | arXiv，matplotlib | 同上 | 无 |
| 验证准确率（网页截图风格） | arXiv，灰色虚线网格，密集的 X 刻度数字 | X 轴 16/17 刻度，Y 轴 7/7；2 条曲线完整 | 无 |
| 损失（网页截图风格） | arXiv，红/橙两条同色系曲线交叉 | X 轴 7/10（密集数字部分连成一串被剔除），Y 6/6；2 条曲线按颜色正确分开 | 无 |
| 应力应变曲线，4 子图 (a)-(d) | MDPI，JPEG，6 条实/虚/点线混合，图例在图内，面板有浅灰边框 | `--panels` 自动拆出 3 个面板（(d) 漏检）；面板 (a) X 12/12、Y 15/16 刻度，曲线按图例命名为 0-PLA/1-PLA/3-PLA/10-PLA/17-PLA，彩色实线完整，点线/点划线部分缺段 | 黑色虚线与浅灰点划线建议 GUI 手动补 |
| I-V 曲线，带照片与示意图插图，对数 Y 轴 | Scientific Reports，JPEG，Y 刻度为 10 的上标 | `--panels` 只拆出真正的坐标系（照片被过滤）；曲线完整；OCR 读不出上标 → `--yticks=0.001,0.01,0.1,1,10 --logy` 与 5 个标签位置一一对应后结果正确（-100 V 处约 2.6 nA，与图一致） | 给刻度值 |
| 几十条彩虹渐变曲线 + 黑色圆点 | MDPI | 标定成功；曲线簇过密被当成实心区域，无法逐条分离 | 超出能力范围 |
| 堆叠柱状图 | arXiv | 标定 Y 轴成功；无曲线（正确：柱状图不是曲线） | 不适用 |

结论：单坐标系、曲线颜色可区分的论文图基本可全自动；多子图需先裁剪；上标对数刻度、
极密集刻度数字需调用方补刻度值；同色多曲线密集重叠无法分离。
