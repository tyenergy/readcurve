# ReadCurve：论文图表 / 表格 → 数据

本 skill 调用 ReadCurve 工具（纯 Python，依赖 numpy、Pillow、rapidocr_onnxruntime），
把论文中的曲线图数字化为 CSV，或把表格图片识别为 CSV。所有步骤走命令行，不开图形界面。

## 0. 定位工具与环境

按顺序找 ReadCurve 根目录 `$RC`（含 `auto_detect.py` 的目录）：

1. 本 skill 文件所在目录的上三级（随仓库一起安装时就是仓库根目录）；
2. 当前项目目录或其子目录里含 `auto_detect.py` 的位置；
3. 都没有则 `git clone https://github.com/tyenergy/readcurve` 到工作目录外的一个固定位置。

首次使用执行 `pip install -r $RC/requirements.txt`。下面的命令都在 `$RC` 目录下运行，
或用绝对路径调用脚本。Windows 下为了避免中文日志乱码，设置 `PYTHONIOENCODING=utf-8`。

## 1. 准备图片

- 已有 PNG/JPG：直接用。
- PDF：先把页面渲染成图片（300 dpi 左右），再裁出目标图表。例如用 PyMuPDF：
  ```python
  import fitz; doc = fitz.open("paper.pdf")
  pix = doc[page_index].get_pixmap(dpi=300); pix.save("page.png")
  ```
  然后看图确定图表的像素范围，用 Pillow 裁剪保存为单独文件。
- 一张图里有 (a)(b)(c) 多个子图时不必手动裁，第 2 步用 `--panels`。

## 2. 曲线图：一键识别

```bash
python auto_detect.py FIG.png -o out.csv --preview check.png            # 单坐标系
python auto_detect.py FIG.png --panels -o out.csv --preview check.png   # 多子图，输出 out_a.csv、check_a.png …
```

读日志，关键行：

| 日志 | 含义 |
|---|---|
| `X 轴：线性，用 18/18 个刻度 [...]` | OCR 标定成功；`对数` 表示自动识别为对数轴 |
| `X 轴：只识别到 N 个刻度数字` / `无法拟合` | 标定失败，转第 3 步 |
| `检测到插图/照片等实心区域…已排除` | 图中照片/模型图已自动排除 |
| `曲线2 → 'measurement'（图例）` | 曲线已按图例命名，CSV 列名随之变化 |
| `识别到 N 条曲线：名字(RGB) 点数[覆盖x% 密度y 断口z]` | 每条曲线的质量指标 |
| `警告：坐标轴未能自动标定，导出的是像素坐标` | 此 CSV 不可用作数据 |

**必须查看 `check.png`**（用读图能力与原图对照）：曲线描线（洋红）是否完整贴合、有无串到别的线或图例上、
标定线（橙色）是否落在正确刻度、绿色排除区是否只盖住插图。任何一项不对，不要采信，转第 3/4 步。

## 3. 标定失败时

常见原因：刻度数字太小或太密、对数轴用 10 的上标、数字被裁掉。按优先级：

1. 自己读图确定刻度值，交给程序匹配刻度线/标签位置（负数用等号写法）：
   ```bash
   python auto_detect.py FIG.png --xticks=0,10,20,30,40 --yticks=0.001,0.01,0.1,1,10 --logy -o out.csv --preview check.png
   ```
   日志会说明匹配了哪些锚点；锚点个数与图上刻度个数不符时不要采信。
2. 直接给像素标定。日志里的 `X 轴旁文本(像素x@文本)` 列出了 OCR 看到的每个文本及位置，对照原图确定它们的值：
   ```bash
   python auto_detect.py FIG.png --cal "x:59=-100,240=100;logy:474=10,710=0.001" -o out.csv --preview check.png
   ```
   每轴两对 `像素=数值`，取相距最远的两个刻度。`--panels`/`--crop` 之后的像素坐标都相对裁剪后的图。
3. 多子图面板漏检时手动裁剪：`--crop x0,y0,x1,y1`（包含刻度数字，不包含面板外框线）。

## 4. 曲线不对时

| 现象 | 处理 |
|---|---|
| 少一条曲线（常见于黑/灰色曲线贴着坐标轴或文字） | `--tol 70` 放宽颜色容差；仍不行则记为需人工 |
| 曲线很密/很粗被当成实心区域排除（日志有提示） | 加 `--no-exclude` |
| 同色曲线交叉后串线 | 用 `--crop` 分段提取后拼接；或记为需人工 |
| 多出假曲线 | 看质量指标：跨度短、密度低的通常是网格/图例残留，忽略对应列 |
| 点线/点划线覆盖不全 | 工具已知局限，记为部分结果 |

## 5. 表格图片

```bash
python table_ocr.py TABLE.png -o table.csv --parsed table_num.csv --preview check.png
```

`table.csv` 为原文单元格；`table_num.csv` 每格拆成（值, 误差）两列，支持 `±`、`×10^n`、科学计数法、百分号。
核对 `check.png`：行带与列线是否与表格一致，表头是否被拆散，长数字是否被截断。
局限：合并单元格只落在起始列；无线条表格中单元格内换行会拆成两行；小字号易混淆 1/l、0/O。

## 6. 输出约定

完成后向调用方报告：

- 每条曲线/每张表的 CSV 路径、列名与含义（对照图例和论文正文）、单位；
- 质量指标与核对结论（"核对图与原图一致" / 哪里不一致）；
- 精度说明：逐像素列采样，约 1 像素，换算成数据单位写出来（例如 x 分辨率 0.02 GHz）；
- 未能提取或存疑的部分明确列出，不要用像素坐标 CSV 冒充数据。

`--mode common --n 200` 可把多条曲线插值到同一组 x，便于与论文表格或复现结果逐点对比。

## 7. 不适用的情况

柱状图、散点图（无连线）、极坐标、三维图、双 Y 轴（需分两次标定）、歪斜的扫描图（先旋转）。
遇到这些要说明工具不适用，由人工或其他方式处理。
